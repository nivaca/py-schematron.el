Subject: nxml: collapsed XSD values keep a space at either end

For the XSD datatypes whose whitespace is collapsed, such as xsd:token
and xsd:NMTOKEN, rng-xsd-collapse-space turns "  abc  " into " abc "
instead of "abc":

  (require 'rng-xsd)
  (rng-xsd-collapse-space "  abc  " #'identity)
  => " abc "

The facets are then checked against " abc ", so a value with a space at
either end fails facets it meets.  For example, nXML reports an error
on <t v="  abc  "/> with

  start = element t { attribute v { xsd:token { maxLength = "3" } } }

and on ed=" #U2" with TEI's teidata.word, an xsd:token with the pattern
"(\p{L}|\p{N}|\p{P}|\p{S})+".  jing accepts both.

The cause is that rng-xsd-collapse-space splits the value with
split-string and a separator regexp, which keeps the empty strings at
either end; they come back as the leading and trailing space.  Omitting
them (OMIT-NULLS) fixes it.

Two smaller things I noticed in rng-xsd: it accepts the time zone
+15:00 in xsd:dateTime (the limit is +14:00), and the year 0000 in
xsd:gYear and the other date types, which XSD 1.0 does not allow (XSD
1.1 does, as 1 BCE).  jing rejects both.

In GNU Emacs 31.1.90 (Fedora 45); the code is the same in master.
