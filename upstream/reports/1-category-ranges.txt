Subject: nxml: xsd-regexp damages its cached category ranges, so \p{P} loses # % ! @

nXML's translation of XSD regular expressions gives different results
each time the same pattern is translated.  After the first use of
\p{P}, the cached ranges of the category Po are cut short, and patterns
using \p{P} no longer match characters such as # % ! @ and ¿.  The same
happens to the last part of every derived category (So in \p{S}, Cn in
\p{C}, and through them \w).

In practice nXML rejects valid documents.  TEI schemas define
teidata.word with the pattern "(\p{L}|\p{N}|\p{P}|\p{S})+", used by
many attributes; with a TEI schema, nXML reports an error on a value
like ed="#U2", which the schema allows.  On 200 TEI editions of mine,
valid for jing, nXML reported such errors in 53.

Recipe, from emacs -Q:

  (require 'xsd-regexp)
  (dotimes (i 3)
    (message "%d: %s" (1+ i)
             (string-match-p (concat "\\`" (xsdre-translate "\\p{P}") "\\'")
                             "#")))

Result:

  1: 0
  2: nil
  3: nil

Expected: 0 each time.  (length (get 'Po 'xsdre-ranges)) goes from 65
to 13.

The cause is in xsdre-range-list-union:

  (xsdre-make-range-list (apply 'append range-lists))

'append' copies all its arguments except the last one, so the last
list is shared with the property 'xsdre-ranges of the last category in
the union, and xsdre-make-range-list then sorts it and merges ranges
in place, with setcar and setcdr.

Copying every list before merging them, the last one included, fixes
it: with that change, the recipe gives 0 three times, and nXML accepts
ed="#U2" again.  (The comment "this fails:" in the test xsdre-matches is
stale: that test passes since bug#24093 was fixed, which concerned
another problem.)

When xsd-regexp is natively compiled, loading it again does not
restore the damaged tables, since the quoted lists are constants of the
.eln file; only a restart of Emacs does.

I am sending three more reports on nXML's XSD datatypes: the categories
are those of Unicode 3.1 and stop at U+FFFF; a class subtraction after a
range is refused; and collapsed whitespace keeps a space at either end.

In GNU Emacs 31.1.90 (Fedora 45); the code is the same in master.
